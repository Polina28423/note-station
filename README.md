# Note Station Rust — первый прототип

Независимый настольный клиент Synology Note Station на Rust + Tauri 2.
Оригинальная сборка в `original/` не изменяется. Код оригинального интерфейса не копируется.

## Возможности

- Вход по HTTPS или явно выбранному HTTP, пароль и необязательный код 2FA.
- Сохранение последнего сервера и имени пользователя на этом компьютере.
- Обнаружение API на NAS, получение блокнотов и заметок с пагинацией.
- Выбор блокнота, поиск по заголовку и чтение текста заметки.
- Обзор блокнотов карточками, счётчики заметок и поиск по блокнотам.
- Закрепление блокнотов отдельно для каждого сервера/пользователя (локально).
- Сортировка, форматированное чтение, масштаб текста и режим на всю ширину.
- Компактное рабочее окно в стиле исходного Note Station: голубое выделение,
  сворачиваемое дерево блокнотов и регулируемая ширина панелей.
- Полки из NAS: вложенные блокноты, сворачивание и просмотр заметок всей полки.
- Сохранение сессии Windows DPAPI, автоматическое восстановление и выход из аккаунта.
- Явное сообщение для зашифрованных заметок вместо попытки показать шифротекст.

Прототип поддерживает чтение и редактирование существующих заметок.
Пока нет создания новых заметок, офлайн-хранилища, загрузки вложений, расшифровки, QuickConnect ID,
расширенной авторизации Secure SignIn и фоновой синхронизации.
Форматирование заметок (заголовки, списки, таблицы, цитаты, выделение и код) сохраняется.
Разметка пересоздаётся по разрешённому списку без серверных атрибутов и активных элементов.
Изображения и вложения пока не показываются, ссылки отображаются текстом.
При включённом сохранении сессия восстанавливается после закрытия и повторного запуска.
Для её удаления и отзыва на NAS используйте «Выйти из аккаунта».

## Запуск Windows

### Разработка в Visual Studio Code

Откройте `NoteStation.code-workspace` через **Файл → Открыть рабочую область из файла**
или выполните из основной папки проекта:

```powershell
code .\NoteStation.code-workspace
```

Настройки находятся в `.vscode/` и работают также при открытии основной папки проекта.
Открывать `original/` для разработки Rust-клиента не нужно.

- `src-tauri/src/main.rs` — точка входа и команды приложения.
- `src-tauri/src/synology.rs` — взаимодействие с API NAS.
- `src-tauri/src/session_store.rs` — хранение сессии.
- `ui/` — HTML, CSS и JavaScript интерфейса.
- **Ctrl+Shift+B** — debug-сборка; **F5** — сборка и отладка Rust;
  **Ctrl+F5** — запуск без отладки.
- **Терминал → Выполнить задачу** — `Rust: run`, `Rust: check`, `Rust: test`,
  `Rust: build release`, `Rust: format`, `UI: test`.
- **F12** — переход к определению; **Shift+Alt+F** — форматирование Rust-файла.

Для подсказок используется `rust-lang.rust-analyzer`, для Windows-отладки —
`ms-vscode.cpptools`. Они перечислены в рекомендуемых расширениях.
На этом компьютере оба расширения установлены; в локальную Rust-среду добавлен `rust-src`.
Настройки соответствуют [официальному руководству Rust в VS Code](https://code.visualstudio.com/docs/languages/rust).

Рабочая область использует Rust из `.tools/cargo` и `.tools/rustup`:
переменные применяются только к её анализатору, задачам и новым встроенным терминалам.
Глобальный PATH не меняется. При переносе на другой компьютер потребуется подготовить
локальную Rust-среду и установить C++ Build Tools / Windows SDK и WebView2.
Каталоги `.tools/` и `target/` скрыты в проводнике VS Code; оригинал и сторонние
JS-библиотеки исключены из общего поиска, но остаются доступны на диске.

F5 отлаживает Rust-код. Для JavaScript интерфейса используйте инструменты разработчика
WebView debug-сборки. После изменения `ui/` пересоберите и перезапустите приложение.

### Запуск из PowerShell

Требуются Rust stable MSVC, Visual Studio C++ Build Tools / Windows SDK и WebView2 Runtime.
Node.js и npm не нужны. Если Rust установлен локально в `.tools/`, скрипт использует его.

```powershell
cd C:\Project\myProject\project-note-station
.\start.ps1
```

Проверки Rust: ` .\start.ps1 -Test `. Проверки сохранения настроек (нужен Node.js):
`node --test tests/preferences.test.mjs tests/library.test.mjs`.
Release-сборка: ` .\start.ps1 -Release ` → `target/release/note-station-rust.exe`.
Для разработки изменяйте `ui/` и `src-tauri/src/`, затем перезапускайте `start.ps1`.
В debug-сборке доступны инструменты разработчика WebView.

Укажите полный адрес NAS вида `https://nas.example:5001`, без `/webman` или `/webapi`.
Note Station должен быть установлен; пользователь должен иметь доступ к нему.
По умолчанию включён HTTPS с проверкой сертификата. Для самоподписанного сертификата раскройте
«Самоподписанный сертификат» и выберите публичный сертификат NAS (или его CA)
в формате PEM: `.pem`, `.crt`, `.cer`, не более 64 КБ, ровно один сертификат,
без закрытого ключа. DER/PFX пока не поддерживаются. Экспортируйте публичный
сертификат через доверенный административный канал NAS; не используйте файл
закрытого ключа из экспортированного комплекта.

Дополнительное доверие действует только для клиента текущего подключения и не
меняет сертификаты Windows. При сохранении сессии PEM сохраняется внутри зашифрованной записи и используется
при её восстановлении; без сохранения после перезапуска его нужно выбрать снова. Для возврата к обычной проверке нажмите
«Убрать сертификат» перед следующим входом. Адрес NAS должен совпадать с SAN
сертификата (для IP нужен IP SAN), а сертификат должен быть действующим.
В обычном режиме проверка имени, срока и TLS-подписи остаётся включённой.

### Подключение без файла сертификата

Выберите в форме режим подключения:

- **HTTPS · без проверки сертификата** — файл PEM не требуется, шифрование есть,
  но подлинность сервера, имя и срок сертификата не проверяются. Возможна подмена NAS.
- **HTTP · без шифрования** — укажите `http://nas.example:5000`. Сертификат не используется;
  пароль, SID и заметки передаются в открытом виде.

Оба режима требуют отметки подтверждения при ручном входе. Сохранённая сессия
восстанавливается в ранее выбранном режиме без повторного ввода пароля. Автоматического
перехода на HTTP или отключения проверки после ошибки нет. При сохранении сессии выбранный режим также запоминается и применяется при восстановлении.
Без сохранённой сессии и после выхода форма снова предлагает обычный HTTPS. Настройки доверия Windows
не меняются. Во время подключения небезопасный режим указан рядом с адресом сервера.

### Запоминание сервера и пользователя

При нажатии «Подключиться» сохраняются только адрес и имя пользователя — даже если NAS
недоступен. Они восстанавливаются при следующем запуске. Для адреса и имени используется локальное хранилище
WebView профиля приложения `local.notestation.rustclient`. Пароль и OTP не сохраняются.
SID, сертификат и режим могут сохраняться отдельно в защищённой записи сессии (см. ниже). URL со встроенными паролями/токенами не сохраняется.
При недоступности хранилища можно подключаться без сохранения.

## Архитектура

- `ui/` — интерфейс и локальные зависимости редактора TinyMCE/DOMPurify в `ui/vendor/`.
- `src-tauri/src/main.rs` — команды сессии, чтения/сохранения заметок и защиты закрытия окна.
- `src-tauri/src/synology.rs` — HTTP(S), каталог API, кодирование запросов, пагинация, ошибки.
- `src-tauri/src/session_store.rs` — атомарная запись сессии, защита Windows DPAPI, загрузка и удаление.
- `src-tauri/tauri.conf.json` — окно и CSP, без shell/filesystem плагинов.

Пароль и SID не пишутся в журналы или браузерное хранилище. Секреты остаются в памяти
во время запросов; гарантированное обнуление всех копий в памяти не реализовано.
Перенаправления запрещены. Путь API из ответа NAS не может менять origin.
Скрипты, внешние ресурсы и атрибуты из заметок не переносятся в документ;
веб-интерфейс не обращается к NAS напрямую.
Ответ ограничен 16 МБ, список — 10 000 записей.

## API и проверка совместимости

Вызовы восстановлены из `original/package.nw/js/background.js`:

| API | Версия / метод | Кодирование |
| --- | --- | --- |
| SYNO.API.Info | 1 / query | form, путь query.cgi |
| SYNO.API.Auth | до 6 / login; 1 / logout | form, путь из каталога |
| SYNO.NoteStation.Notebook | 2 / list | значения полей JSON в form |
| SYNO.NoteStation.Note | 2 / list, get | значения полей JSON в form |

Совместимость с конкретным NAS необходимо проверить: вход → блокноты → список → чтение → выход.
Автотесты проверяют локальную валидацию, кодирование и реальные HTTP/TLS на loopback:
самоподписанный сертификат без доверия отклоняется, выбранный сертификат принимается,
несовпадающее имя и истёкший срок отклоняются до передачи HTTP-запроса. Ключи тестов генерируются
в памяти. Отдельно проверены явное отключение TLS-проверки и обычный HTTP, а также
сохранение только разрешённых полей и восстановление после ошибок хранилища.
Базовый сценарий входа, загрузки блокнотов/заметок и чтения на реальном NAS подтверждён
пользователем. Новый интерфейс дополнительно проверен на демонстрационных данных.
Никогда не присылайте пароль, SID или HAR с cookies для диагностики. Достаточно кода ошибки
и обезличенной структуры ответа. Следующий этап — проверка на тестовом NAS, затем редактор и сохранение.

Документация: https://v2.tauri.app/develop/ и https://kb.synology.com/en-uk/DG/DSM_Login_Web_API_Guide/3 .

## Работа с библиотекой

После входа открываются все заметки в трёх панелях: навигация, список, документ.
Нажмите название блокнота слева, чтобы отфильтровать заметки. «Обзор блокнотов» открывает
дополнительный режим карточек. Звезда закрепляет блокнот в разделе «Ярлыки»; NAS при этом не изменяется.
Список блокнотов сворачивается кнопкой с треугольником. Разделители панелей можно
перетаскивать мышью или менять стрелками влево/вправо после фокусировки клавишей Tab.
Краткое описание и дата изменения показываются в списке заметок, если NAS возвращает эти поля.
Полки восстанавливаются из поля `stack` ответа `SYNO.NoteStation.Notebook/list` —
так же, как в оригинальном клиенте. Дерево показывает «полка → блокноты», а блокноты
с пустым/отсутствующим `stack` остаются на верхнем уровне. Выбор названия полки показывает
заметки всех её блокнотов. Треугольник сворачивает только содержимое; состояние сохраняется
при обновлении текущей сессии и временно раскрывается для результатов поиска.
Поиск поддерживает названия полок и блокнотов. В обзоре карточки сгруппированы по полкам,
блокноты без полки вынесены в отдельный раздел. Ярлык не убирает блокнот из своей полки.
Полки с одинаковыми именами разных владельцев группируются отдельно.
Создание, переименование и перемещение полок/блокнотов на NAS пока не реализованы.
Поиск в левой панели фильтрует блокноты, поиск над заметками — заголовки в текущем блокноте.
«Все заметки» показывает общую коллекцию. Обновление перечитывает и блокноты, и заметки.

В списке заметок доступны сортировка и перемещение стрелками вверх/вниз.
Ctrl+K переводит фокус в поиск. Кнопка ⛶ раскрывает чтение на всю ширину; Esc возвращает
обычный вид. A−/A+ меняют размер текста, «Копировать» копирует обычный текст заметки.

Предпросмотр для разработки: `python tests/serve-preview.py`, затем
`http://127.0.0.1:8765/`. Он использует исключительно вымышленные данные;
mock API и тесты не включаются в EXE. Проверки безопасной разметки доступны по
`http://127.0.0.1:8765/content-check.html`. Предпросмотр не подключается к NAS.


## Сохранение сессии и выход

После обновления войдите один раз с включённой галочкой «Сохранять сессию».
При следующем запуске клиент расшифрует SID и проверит его запросом к NAS,
без повторного использования пароля или обхода 2FA. Срок действия определяет NAS.
Если пользователь уже вошёл без сохранения, кнопка «Сохранить сессию» в верхней
панели сохраняет текущий вход. Нажатие «Сессия сохранена» отключает автологин,
сохраняя текущую работу до закрытия приложения.

На Windows запись находится в `%LOCALAPPDATA%/local.notestation.rustclient/session.bin`.
Она содержит SID, сервер, имя, режим подключения и необязательный PEM; вся запись
защищена DPAPI для текущего пользователя Windows, без машинного режима и без ключа
рядом с файлом. Пароль/OTP не входят в запись. DPAPI не защищает от процессов,
работающих с правами того же пользователя. Служебные копии SID и расшифрованный JSON
обнуляются при освобождении, но гарантированное удаление всех копий памяти не обещается.
Для других ОС сохранение пока недоступно; вход без сохранения остаётся доступным.

При недоступном NAS запись сохраняется, доступны «Повторить подключение» и
«Забыть сессию». При кодах истёкшего SID 106/107/119 запись удаляется и нужен новый вход.
Повреждённую/недоступную запись можно удалить кнопкой «Забыть сессию».

«Выйти из аккаунта» сначала удаляет локальную запись, очищает активную сессию,
затем запрашивает выход на NAS. Если NAS недоступен, приложение сообщает, что серверный
отзыв не подтверждён; локальный вход всё равно удалён. При ошибке удаления файла выход
не объявляется завершённым — можно повторить. Сервер и имя пользователя остаются
сохранёнными, заметки и блокноты на NAS не изменяются.

Проверены шифрование/повторное открытие/перезапись/удаление на Windows, отклонение
повреждённого файла и различение сетевых ошибок и истечения SID. В интерфейсе на
вымышленных данных проверены восстановление после перезагрузки, выход, отсутствие
автовхода после выхода и временная сессия без сохранения. Повторный вход на реальном
NAS после обновления должен выполнить пользователь; срок сессии зависит от NAS.


## Редактор заметок

Откройте заметку и нажмите «Редактировать». Доступны заголовок, визуальное
форматирование, заголовки, списки, таблицы, ссылки и HTML-код. Сохранение — кнопка
«Сохранить на NAS» или Ctrl+S. «Отмена» возвращает чтение. При переходе, обновлении,
выходе и закрытии окна предлагается сохранить, отбросить изменения или продолжить
редактирование. Черновики пока хранятся только в памяти; восстановления после аварии нет.

Используется локальный TinyMCE 8.10.2 и DOMPurify 3.4.17. Лицензии и источники указаны
в `THIRD_PARTY_NOTICES.md`; TinyMCE включён в GPL-режиме. Node.js/npm для запуска
и обычной Rust-сборки не нужны: файлы редактора уже находятся в `ui/vendor/`.

Запись использует `SYNO.NoteStation.Note` v3, `method=set`, с `object_id`, исходным
`ver`, `check_conflict=true`, `title`, `content`, `brief` и сообщением версии.
Перед записью также читается свежая версия; устаревший документ не перезаписывается.
Права проверяет NAS. Зашифрованные заметки и заметки без версии не редактируются.
После подтверждённой записи выполняется чтение актуального документа; сбой этого
чтения отмечается отдельным уведомлением, а не ошибкой самой записи.

Изображения, PDF и другие существующие медиа в редакторе заменены защищёнными
заглушками. При сохранении ссылки и исходная метаинформация возвращаются в HTML.
Редактор не отправляет команды изменения/удаления файлов-вложений. Удаление заглушки
убирает ссылку из текста; новый файл не загружается. При изменении только заголовка
исходный HTML сохраняется без нормализации. При изменении текста допускается
нормализация поддерживаемого HTML редактором; специальные конструкции Synology,
кроме защищённых медиа, могут отображаться иначе. Встроенные скрипты не исполняются.

CSP сохраняет локальный `script-src` и запрещает внешние фреймы и ресурсы.
Для iframe редактора разрешён `frame-src 'self'`, для форматирования — inline-стили.
Новая HTML-разметка проходит DOMPurify; существующие защищённые медиа не вставляются
в живой DOM редактора и не загружаются.

Проверки включают реальный HTTP-обмен с тестовым сервером: версия и `check_conflict`,
отказ при устаревшей версии, отсутствие мутаций вложений, подтверждённая запись
при неудачном повторном чтении. В браузере проверены заголовок, текст, форматирование,
Ctrl+S, сохранение при переходе, отмена и сохранность черновика при ошибке.
`/editor-check.html` на сервере предпросмотра проверяет сохранность ссылок и очистку
разметки через настоящий TinyMCE. Сохранение на реальном NAS после добавления редактора
ещё не проверено; начните с отдельной тестовой заметки.


## Запуск с действующей сессией

Форма входа скрыта уже в начальном HTML. До ответа `restore_session` отображается
отдельный экран подключения, затем сразу библиотека. Форма показывается только
при отсутствии сессии или подтверждённой необходимости повторного входа.
Если NAS недоступен, предлагается повторить подключение, войти вручную или выйти
из аккаунта; сохранённый SID при сетевой ошибке не удаляется. Модуль `ui/startup.js`
